## 📄 概要
社内の会議室や備品などの管理状況を可視化し、業務が円滑に進むためのツールです。カレンダーから直感的に操作を行えるため、
登録した備品や会議室に対してわかりやすく確認が可能です。

## 📦 機能一覧(Features)

- **会議室や備品の登録機能**：カレンダーから予約する際に任意の各々を予め登録しておけます。
- **予約登録機能**：特定の日時、使用目的を指定した予約の作成が可能です。
- **予約管理機能**：ユーザー機能の追加はまだですが、現状でも日時の変更や、削除も行えます。
- **バリデーション**：開始時刻が終了時刻よりも遅い日時を予約を制御します。

## 🛠️ 技術スタック (Tech Stack)

-  Frontend：React,Vite
-  Backend： Node.js,Express.js

##  🏗️ 設計思想・アーキテクチャ(Architecture)

開発の初期段階で、保守性と拡張性を意識した**MVCS(Model-View-Controller-Service)アーキテクチャ**を採用しました

---

![Architecture diagram ](./images/mermaid_mvcs_model.png)

---

### こだわったポイント

- **UIとロジックの分離(Frontend)**
  Reactコンポーネント(View)から、ロジックをhooksとして分割し、UIコンポーネントの肥大化と密結合を防ぎました。

- **責任の分離(Backend)**
  1. **Controller**：リクエストのバリデーションと、クライアントへ返却する際のレスポンスエラーハンドリングを担当
  2. **Service**：ビジネスロジック（重複判定など）を非同期で集約。DB操作とは切り離して管理。
  3. **Repositories**：データベースへのCRUD操作（読み書き）などを担当

- **メリット**
  それぞれの役割が明確になり、変更に強くバグの影響範囲の限定が容易になりました。

##  💾 データベース設計(Database Schema)

PostgreSQLを使用し以下のリレーションでデータを管理しています。

- **reservables**(会議室・備品管理マスタ)
    - `id` (PK): 一意なID
    - `name`: 会議室名や備品名
    - `type`: カテゴリ（会議室/プロジェクター等）
    - `isActive`: 有効かどうか
      
- **reservations**(予約データ)
     - `id` (PK) : 予約ID
     - `reservable_id`: reservablesテーブルへの外部キー
     - `user_id`: 予約者ID(将来的な機能拡張用)
     - `start_time`: 利用開始日時
     - `end_time`: 利用終了日時
       
- **関係性**: `reservables`(1) : `reservations`(N)

## 今後の展望 / 未実装機能

現在はポートフォリオ用に開発しているため以下の機能を今後実装していけたらと思っています。

- **ユーザー認証機能**：組織単位での予約機能や、ユーザー毎の管理権限（削除などを容易に出来ないように）

## 💡 工夫した点・苦労した点

-  **状態管理**：Reactなどのフロントエンドにおけるレンダリング時の適切に行うための実装や、サーバーから取得した最新のデータを表示させる設計
- **アーキテクチャ**：初めてのMVCSアーキテクチャにおいて、まずは関数型から書いていき、いざリファクタリングするとなった時に、どこに何をおけば良いのかの判断
-  **UI/UX**：実際に一通り完成して動かせるようになってから初めて気づいた扱いづらさや、不具合などの、完成した後のコードの修正
